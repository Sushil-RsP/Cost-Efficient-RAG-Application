Section 02

EDA & Data Cleaning Pipeline for ML

Rigorous data preparation strategies to prevent garbage-in, garbage-out outcomes.

Handling Missing Values

Mean vs. Median vs. Mode

Use Median for skewed continuous data (e.g., Income), Mean for normally distributed continuous features, and Mode for categorical variables.

Indicator Columns (`is_missing`)

Create explicit binary flags (`is_null_age = 1`) prior to imputation. Missingness itself is often a predictive business signal.

When to Drop vs. Impute

Drop columns if missingness exceeds $40$-$50\%$ unless missingness is informative. Drop rows only if missingness is completely random and dataset size is ample.

Outlier Detection & Treatment

IQR Method (Non-parametric)

Bounds = [Q1 - 1.5×IQR, Q3 + 1.5×IQR]

Robust against extreme skewed values. Ideal for e-commerce order amounts.

Z-Score Method (Parametric)

Flag if |Z| > 3 where Z = (X - μ) / σ

Suitable only for approximately normally distributed features.

Winsorizing / Capping

Cap values at 1st and 99th percentiles rather than deleting data points, retaining sample size while curbing extreme leverage.

Categorical Encoding & Feature Scaling Trade-offs Cheat Matrix
Technique Best Used For Business / Model Trade-off
One-Hot Encoding Nominal data with low cardinality (< 10 unique categories) Prevents false ordinal assumptions, but inflates feature dimensionality (Curse of Dimensionality).
Ordinal Encoding Categorical data with explicit rank (e.g., Low, Med, High) Preserves inherent order efficiently without adding columns.
Target Encoding High cardinality (e.g., Zip Codes, Product IDs) Compact representation; highly prone to target leakage if un-smoothed.
StandardScaler Distance-based models (SVM, KNN) & Linear/Logistic Regression Centers data (Mean=0, Std=1). Sensitive to extreme outliers.
MinMaxScaler Neural Nets or algorithms requiring bounded range [0,1] Preserves zero values in sparse matrices, but severely compressed by outliers.
Log Transformation Right-skewed monetary features (Revenue, Spend) Compresses long tails, making distributions normal and improving linear model fit.
Section 03

Analytics-Driven ML Models

Interpreting core machine learning algorithms for business decision-makers.

Regression Models

Interpretable

Linear ($\hat{y} = \beta_0 + \beta_1 X$) & Logistic ($\ln(\frac{p}{1-p}) = \beta X$)

  • Odds Ratios: In Logistic Regression, $e^{\beta_i}$ represents the multiplicative change in odds per unit change in $X_i$.
  • Stakeholder Value: Direct explanation of driver impact ("Every \$100 discount increases conversion odds by 25%").

Trees & Forests

Non-linear

Decision Trees, Random Forest, Gradient Boosting

  • Gini vs Entropy: Measures split impurity. Gini is computationally faster; Entropy measures information gain.
  • Partial Dependence Plots (PDP): Show the marginal effect of 1 or 2 features on model predictions.

K-Means & RFM

Unsupervised

Recency, Frequency, Monetary Segmentation

  • Elbow Method: Plot Within-Cluster Sum of Squares (WCSS) vs $K$ to spot inflection point.
  • Silhouette Score: Quantifies cluster separation $[-1, +1]$. Higher means tighter, distinct clusters.
Section 04

Business Evaluation Metrics

Translating statistical metrics into financial terms and stakeholder BI outputs.

Regression Error Translation

MAE (Mean Absolute Error): "On average, our prediction is off by \$25." Highly interpretable by executives.
RMSE (Root Mean Squared Error): Penalizes large errors heavily. Crucial if large mispredictions carry disproportionate financial penalties.
MAPE (Mean Absolute Percentage Error): "Our forecasts are off by 4.2% on average." Standard for executive scorecards.

Classification Trade-off Dynamics

Precision Focus: Minimizes False Positives. Essential when action cost is high (e.g., expensive retention gifts).
Recall Focus: Minimizes False Negatives. Essential when missing a target is catastrophic (e.g., fraud, high-LTV churn).
Exporting to BI Tools: Output predicted probabilities (`y_proba`) into SQL/Power BI tables to let stakeholders dynamically adjust threshold sliders.
Section 05

Hyperparameter Tuning & Data Leakage

Methodologies for model optimization and avoiding overoptimistic evaluation.

Tuning Strategies

  • GridSearchCV: Exhaustive search over specified parameter grid. Guarantees finding best combination in grid, but computationally expensive.
  • RandomizedSearchCV: Samples fixed number of parameter settings from specified distributions. Much faster with minimal performance loss.

Preventing Data Leakage

Preprocessing Leakage: Scaling/Imputation MUST be fit only on the training set (`fit_transform` on train, `transform` on test).
Temporal Leakage: For time-series data, never use random train-test split. Use `TimeSeriesSplit` to respect temporal ordering.

Copyable production snippets for Pandas, Scikit-Learn pipelines, and SQL window feature engineering.

Python Scikit-Learn Preprocessing Pipeline 
import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.compose import ColumnTransformer
from sklearn.pipeline import Pipeline
from sklearn.impute import SimpleImputer
from sklearn.preprocessing import StandardScaler, OneHotEncoder
from sklearn.ensemble import RandomForestClassifier

# Numeric and Categorical Column Definitions
num_features = ['age', 'income', 'tenure']
cat_features = ['segment', 'region']

# Building Preprocessing Transformers
num_transformer = Pipeline(steps=[
    ('imputer', SimpleImputer(strategy='median')),
    ('scaler', StandardScaler())
])

cat_transformer = Pipeline(steps=[
    ('imputer', SimpleImputer(strategy='most_frequent')),
    ('onehot', OneHotEncoder(handle_unknown='ignore'))
])

preprocessor = ColumnTransformer(
    transformers=[
        ('num', num_transformer, num_features),
        ('cat', cat_transformer, cat_features)
    ])

# Final Pipeline
full_pipeline = Pipeline(steps=[
    ('preprocessor', preprocessor),
    ('classifier', RandomForestClassifier(n_estimators=100, random_state=42))
])

# Fit Pipeline cleanly preventing leakage

SQL Window Feature Engineering for Churn 
WITH user_activity AS (
    SELECT 
        user_id,
        COUNT(order_id) AS total_orders_l30d,
        SUM(order_amount) AS total_spend_l30d,
        MAX(order_timestamp) AS last_order_date
    FROM orders
    WHERE order_timestamp >= CURRENT_DATE - INTERVAL '30 days'
    GROUP BY user_id
)
SELECT 
    u.user_id,
    u.signup_date,
    COALESCE(a.total_orders_l30d, 0) AS total_orders_l30d,
    COALESCE(a.total_spend_l30d, 0.0) AS total_spend_l30d,
    DATE_PART('day', CURRENT_DATE - a.last_order_date) AS days_since_last_order,
    -- Label definition: 1 if user made zero purchases in the last 60 days
    CASE WHEN a.last_order_date IS NULL THEN 1 ELSE 0 END AS is_churn_risk
FROM users u
LEFT JOIN user_activity a ON u.user_id = a.user_id;
